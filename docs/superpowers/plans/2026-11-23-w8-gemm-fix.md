# W=8 MMA / GEMM Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the `mma` instruction collect the ISA-defined `B[K−1]` column at W=8 on K=16 and K=32, so the board grouped GEMM produces correct results and nonzero effective MACs.

**Architecture:** The board evidence is that the W=8 collector selects `B[0]` instead of `B[K−1]`: the silicon one-shot returns `C + A[i]` when the test puts `B[0]=1`, while the ISA and the old W=4 `engine_smoke4` expect `A[i]·B[K−1]`. The simulator specs pass because their assertions accept any matching column. The fix is test-first: pin the exact ISA column, bisect the lane selector (`DataCollector` / `DataFeeder` / `NpuProgramEngine` `slots`/W path), fix the source, then rebuild the K16/K32 releases and board bitstreams and verify the GEMM and effective MACs on both boards.

**Tech Stack:** Scala 2.13 / Chisel 6.7 / sbt, `EphemeralSimulator`, ScalaTest, Vivado 2025.2, XDMA, NPUCTL, the platform host scripts.

**Spec:** `docs/designs/01.isa.md` (`mma vd, vs1, vs2, vs3` ⇒ `vd[i] = A[i]·B[K−1] + C[i]`; `vs3 = x0` means zero C), `docs/designs/04.streamed-issuing.md` (dispatch/capture chaining), `docs/designs/07.npuctl-v1.md` (segment map), and the board docs in `~/chisel-npu-platform/docs/FPGA_XC7K480T.md` and `FPGA_VU9P.md`.

## Global Constraints

- The ISA is frozen: `mma` collects the **B[K−1]** column. Do not redefine the instruction or move the matrix element to lane 0 in the driver as a workaround.
- The release under test is `NpuPeripheral(K=32, N=8, W=8)` on vu9p and the K=16/L=16 parameterization on xc7k; both run at 100 MHz.
- The old W=4 16×16 `engine_smoke4` test 1 (`A[i]·B[15] + C[i]`) and the board `vle8`/`vse8`/B-copy results are the reference behavior.
- Every MMA result assertion must require the exact ISA column; `cols.nonEmpty` / any-column tolerance is forbidden.
- `MACS` counts issued K² MACs, not correctness; effective MACs are the correct MACs and must be nonzero before the fix is called complete.
- No RTL fix may change the NPUCTL register map, the public ports, the ISA, or the board segment layout.

## Review Focus

1. **Collector lane:** W=4 vs W=8 and K=16 vs K=32 must all select `B[K−1]`; a per-`W` or per-`K` difference is the most likely failure.
2. **`mma.last`:** it is a group marker, not a second feed; its `vs1/vs2/vs3` values must not alter the captured column or add an extra MAC.
3. **Register class/alias:** VX0/VX1 vs the simulator's VX4/VX8, and the VR result alias, must not change the selected B lane.
4. **Board segment map / long program:** the five bases/limits, `PROG_LEN`, `ENTRY_PC`, and the long grouped code must not shift the A/B/C addresses.
5. **Issued vs effective MACs:** the counter can rise while the result is wrong; the board verification must check the reference result and report effective MACs separately.
