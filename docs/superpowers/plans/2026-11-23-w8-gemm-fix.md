# W=8/per-mma MMA `B[K-1]` capture — hybrid design + implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every `mma`/`mma.last` a real feed that writes its own `VR[vd]`, and make the deterministic round-final capture the ISA column `B[K-1]`, so the board one-shot and grouped GEMM are bit-exact and the achieved issue/feed throughput is preserved.

**Architecture (decided with the human partner):**
- `mma vd, vs1, vs2, vs3` feeds one real `(A,B)` term into the systolic array; `mma.last` is the same feed plus the round-end marker. No A/B/C zero-forcing.
- The PEs accumulate across a round; the `mma.last` drives `keep=0`, which resets the next round's first feed (existing pipeline behavior).
- **Every** `mma`/`mma.last` captures and writes its own `VR[vd]`. Non-last writes are running-sum partials (the pre-reduce `d325cf1` behavior); the `mma.last` write is the deterministic accumulated column `K-1`.
- The normal collector path already emits one full FIFO-aligned column per cycle (feeder `Pipe(i)` + systolic skew + collector `Pipe(n-1-i)`), so a per-feed capture is a single-cycle full-column read, not a row-by-row assembly. The limitation is capture **phase**: the engine's `clctD` samples 16 cycles after the array's valid window, so the sampled column is whatever `cnt` selects (consecutive feeds → consecutive columns). Forcing `K-1` for every feed at 1 feed/cycle needs per-feed phase alignment (a delayed copy/rotation of the aligned column) or paced feeds. The round-final `K-1` uses a reset-wave row-latch because the array's final column is valid for only one cycle per row, 16 cycles before `clctD`.
- Board one-shot = **one real `mma.last`**. Board GEMM = **one round per output column**: `NK` feeds (the last is `mma.last`), `B[t][j]` placed at lane `K-1`, `C=0`, one `vse`. This is the measured feed/round shape, not the serial C-chain shape.

**Spec:** `docs/designs/01.isa.md` (MMA), `docs/designs/04.streamed-issuing.md` §14, the pre-reduce silicon reference `d325cf1` (`capturePush = !compLast`, `test_session_captures_columns`).

## Global Constraints

- ISA encoding frozen; `mma`/`mma.last`/`mma.reset` unchanged. `mma.last` is a real feed + round end.
- No zero-forcing of `mma.last` A/B/C.
- Every `mma`/`mma.last` writes its own `VR[vd]`. Non-last values are partials; do not claim they are `B[K-1]`.
- The round-final (`mma.last`) capture MUST be exactly `vd[i] = A[i]·B[K-1] + C[i]` for K=16 and K=32, W=4 and W=8.
- Tests must not use any-column tolerance for the round-final/one-shot result.
- No NPUCTL register-map, port, AXI-translation, or segment-layout change.
- No added latency in the capture tick: the round-final snapshot still presents at `clct + CAPTURE_DELAY`.
- Preserve the measured issue/feed performance: NOP IPC ~0.98, feed/round MACs/cyc; report **absolute GMAC/s** at 100 MHz as well as MAC/cyc and IPC.
- Do not move the B element to lane 0 in the driver or RTL as a workaround.
- Timing fixes may only register/reorder existing logic. They must not change the ISA, the issue/feed latency, the capture tick, or the NPUCTL register map/ports.

## Root cause (verified, not hypothesized)

1. `dataCollector.scala:128,132` — the per-round snapshot reads `io.reg_in(i*n + 0)`, i.e. **physical column 0** = `B[0]`, and `:193` makes it override the normal output at the engine's `clct+16` sample. Board evidence: `b[0]=1` gives `C + A[i]` on both boards. This is the release-level bug; the W=8 sim specs hid it with `cols.nonEmpty`.
2. `npuProgramEngine.scala:882-883,929` — reduce-only commits only the `mma.last` capture, so the snapshot's column 0 is the only visible result.
3. `npuProgramEngine.scala:864-865` — `mma.last` zero-forces A/B, so the pre-reduce per-mma capture, the ISA "same feed + end" semantics, and the board `mma`+`mma.last` C-chained GEMM are all broken.
4. The board grouped GEMM script is the pre-reduce-only two-columns-per-round C-chain shape; it cannot be correct with PE accumulation.

### Task 2b: Timing closure — break the segment-fit → store-data path

**Evidence (routed report `/tmp/opencode/timing_routed.rpt`, 10 ns fabric):**

```
Worst intra-fabric path: -0.506 ns, 17 logic levels, 9.612 ns data
  (logic 1.379 ns, route 8.233 ns = 85.6%)
  segLimit_3_reg -> effLimit/activeLimit (hub) -> awFits (7x CARRY4, 13-bit
  compare `off + vecBytes <= seg_limit`) -> vrPending valid/dataReady/inFlight
  -> vrPending_storeData_15_reg[1]/CE   (fanout 1024)
```

The 13-bit segment-fit comparator and the wide `vrPending.storeData` CE are in the same clock cycle as the store issue. This is the K=32 100 MHz limiter (~9.624 ns in the verified build, WNS +0.376). It is not in the MMA array.

**Files:** `src/main/scala/engine/npuProgramEngine.scala`, `src/main/scala/peripheral/NpuControlHub.scala` (only if the limit mux needs it).

- [ ] **Step 1: Drive the core-facing limits from the latched registers.** In `NpuControlHub.scala`, `io.seg_limit`/`io.core_seg_limit`/`io.seg_base` currently select `Mux(activeNow, activeLimit, effLimit)`, where `effLimit` is combinational from `segLimit`. Drive the core-facing values from the **registered** `activeLimit`/`activeBase` directly (the core only uses them while running; the `codeFits` start check still uses `effLimit`). This removes `segLimit -> effLimit -> Mux` from the core path. Also register `io.seg_limit` into a local `segLimitR` in the core as belt-and-braces.

- [ ] **Step 2: Compute the address fit at slot entry.** Add `fits: Bool` to `DispatchSlot`. At entry: `fits := (mem_off + vecBytes) <= segLimitR(sect)` for LD/ST, `true` otherwise. At issue use `slots(s).fits` (a registered bit) instead of recomputing `dmaFits`. The 13-bit CARRY chain leaves the issue cycle.

- [ ] **Step 3: Decouple the pending store data from the fit/valid cone.** Write `vrPending.storeData` from the RF read with a local enable (`isVrStore && issueSel(s)`), and gate only `vrPending.valid`/`vrPendingValid` with `fits`. The fit comparator must not reach the 1024-flop `storeData` CE. On `!fits`, still set `dmaFault`/`done` as today.

- [ ] **Step 4: Shorten the per-mma write-mask cone.** Register `capMask := (0xF << (capVd<<2))` at `compValid` and use it for the `wrDone` update at `clctPrev`, so the per-mma capture does not put a dynamic 5→32 decoder on the `wrDone` increment path. Do the same for the entry `entSwmask`/`entSrmask` if the post-synth report puts them on the critical path (register the mask in the slot).

- [ ] **Step 5: Verify timing.** Rebuild the K=32 netlist at 10 ns (the platform flow `FABRIC_PERIOD=10.000` assert) and report the new worst intra-fabric path. Target: WNS ≥ the verified +0.376 ns with the new logic, and record the new worst path. Do not change the ISA, issue/feed latency, or NPUCTL map to buy timing; only register/reorder existing logic.
