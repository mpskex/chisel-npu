# NPUCTL v1 — NPU control protocol

**Status:** normative, v1.0 (2026-11-22)

This document defines the control-plane contract between a host and an NPU
`NpuPeripheral`. It is transport-agnostic: the peripheral exposes a simple
valid/ready register bus internally, and the board supplies an AXI4-Lite or
APB adapter. The data plane is a separate AXI4 master.

The v1 protocol relocates the existing NPU sections. It does **not** change
the ISA, the instruction stream, or the 4 KB per-instruction reach. Segment
base registers move the sections; widening the reach is a separate IP-centric
project.

## 1. Transport

```
req_valid, req_write, req_addr[11:0], req_wdata[31:0], req_wstrb[3:0] -> req_ready
resp_valid, resp_rdata[31:0], resp_error <- resp_ready
```

- 32-bit little-endian registers, 4-byte aligned.
- One request at a time. A write response carries `rdata = 0`.
- The AXI4-Lite adapter maps `resp_error` to `SLVERR`. The v1 hub itself
  always returns OKAY; the data-plane guard reports bus errors through
  `IRQ_STATUS.BUS_ERROR` and `ERROR_CODE`.
- The data plane is AXI4: 64-bit system address, 512-bit data, INCR bursts.
  `CAPS.AXI_DATA_W` reports `log2(bytes per beat)` (512 bits -> 6).

## 2. Register map

| Offset | Name | Access | Semantics |
|---|---|---|---|
| `0x000` | `ID` | RO | magic `0x4E505531` ("NPU1") |
| `0x004` | `VERSION` | RO | major[31:24], minor[23:16], patch[15:8], reserved[7:0] |
| `0x008` | `CAPS` | RO | see §3 |
| `0x00C` | `CONFIG` | RO | K[7:0], N[15:8], L[23:16], W[31:24] |
| `0x010` | `CONTROL` | W | bit0 `START`, bit1 `STOP/ABORT`, bit2 `SOFT_RESET` (self-clearing) |
| `0x014` | `STATUS` | RO | see §4 |
| `0x018` | `IRQ_STATUS` | W1C | bit0 `DONE`, bit1 `ERROR`, bit2 `TRACE_OVF`, bit3 `BUS_ERROR` |
| `0x01C` | `IRQ_ENABLE` | RW | same bits |
| `0x020` | `ERROR_CODE` | RO | see §5 |
| `0x024` | `ERROR_PC` | RO | faulting PC (16-bit, zero-extended) |
| `0x028` | `ERROR_INFO` | RO | faulting instruction word |
| `0x02C` | `ERROR_ADDR` | RO | `{seg[2:0], offset[28:0]}` for a memory fault; 0 otherwise |
| `0x030` | `PROG_LEN` | RW | instruction count in words |
| `0x034` | `ENTRY_PC` | RW | entry word offset (default 0) |
| `0x038` | `SESSION_ID` | RW | host cookie; low byte appears in the trace START record |
| `0x03C` | `WATCHDOG` | RW | cycles; 0 = off |
| `0x040` | `CYCLES` | RO | last session cycles, latched at done/error |
| `0x044` | `MACS` | RO | last session useful K² MACs, latched |
| `0x048` | `FETCH_STATS` | RO | prefetches[31:16] / misses[15:0], latched |
| `0x04C` | `TIMESTAMP` | RO | free-running 32-bit cycle counter |
| `0x050` | `TRACE_CTRL` | RW | bit0 enable; mode[3:1]; divider[15:8] (reserved, 0) |
| `0x054` | `TRACE_STATUS` | RO | count[15:0]; overflow bit16; full bit17 |
| `0x058` | `TRACE_DATA` | RO | pop one 32-bit half of a 64-bit record |
| `0x05C` | `TRACE_DROPS` | RO | dropped record count |
| `0x100 + 16*i + 0x0` | `SEG_BASE_LO` | RW | segment i system base, low 32 bits |
| `0x100 + 16*i + 0x4` | `SEG_BASE_HI` | RW | segment i system base, high 32 bits |
| `0x100 + 16*i + 0x8` | `SEG_LIMIT` | RW | segment i byte limit; 0 = default window |
| `0x180` | `SCRATCH0` | RW | software scratch |
| `0x184` | `SCRATCH1` | RW | |
| `0x188` | `SCRATCH2` | RW | |
| `0x18C` | `SCRATCH3` | RW | |

Segment indices: 0 A, 1 B, 2 ACCUM, 3 OUT, 4 CODE. Entries 5..31 are
reserved for future IP variants; v1 implements 5 active entries.

`TRACE_DATA` reads are paired: the first read returns bits [31:0] of the
record at the FIFO head, the second returns bits [63:32] and pops the record.
If the FIFO is empty, both return 0. The trace stream and `TRACE_DATA` should
not be used simultaneously; the stream pauses while a half-record read is
pending.

## 3. CAPS fields

| Bits | Field | v1 |
|---|---|---|
| `[3:0]` | feature bits | b0 IRQ, b1 TRACE, b2 WATCHDOG, b3 AXI64 |
| `[7:4]` | reserved | 0 |
| `[11:8]` | `NUM_SEG` | 5 |
| `[15:12]` | `LOCAL_MAP` | 1 |
| `[23:16]` | `TRACE_DEPTH_LOG2` | 8 (256 records) |
| `[27:24]` | reserved | 0 |
| `[31:28]` | `AXI_DATA_W` (log2 bytes) | 6 (512 bits) |

The `LOCAL_MAP` value describes the core-side flat offsets:
A=`0x0000`, B=`0x0400`, ACCUM=`0x0800`, OUT=`0x0880`, CODE=`0x4000`.
These are internal; software only writes system bases.

## 4. STATUS

| Bits | Meaning |
|---|---|
| `[0]` | `BUSY` — session running (or the core is busy) |
| `[1]` | `DONE` — sticky success, cleared by START/SOFT_RESET |
| `[2]` | `ERROR` — sticky fault, cleared by START/SOFT_RESET |
| `[3]` | `ABORTED` — sticky host abort |
| `[7:4]` | state: 0 IDLE, 1 RUN, 2 DONE, 3 ERROR, 4 ABORTED |
| `[30:8]` | reserved |
| `[31]` | live `irq` |

`irq = |(IRQ_STATUS & IRQ_ENABLE)`.

## 5. Error codes

| Code | Name | Cause |
|---|---|---|
| 0 | NONE | no error |
| 1 | ILLEGAL | decoder-illegal or unsupported instruction |
| 2 | MEM_FAULT | segment-relative access outside `SEG_LIMIT` |
| 3 | WATCHDOG | `WATCHDOG` expired while running |
| 4 | BUS_ERROR | data-plane guard fired |
| 5 | BAD_CONFIG | `PROG_LEN=0`, misaligned base, non-64-multiple limit, code window overflow, or `ENTRY_PC + PROG_LEN > 0xFFFF` |
| 6 | ABORTED | host STOP |

`ERROR_*` latches the first fault of a session. A new START clears it.

## 6. Control semantics

- `START` requires `PROG_LEN > 0`, every segment base 64-byte aligned, every
  effective limit a multiple of 64, `ENTRY_PC + PROG_LEN <= 0xFFFF`, and the
  code window (`ceil((ENTRY_PC+PROG_LEN)/16)*64`) within the CODE limit.
- On a valid START: snapshot `SEG_*`, `PROG_LEN`, `ENTRY_PC`, and `WATCHDOG`
  into active shadows; clear `DONE/ERROR/ABORTED` and `IRQ_STATUS`; pulse the
  core start. Writes to the programming registers while busy do not affect
  the running session.
- On a successful drain: set `DONE`, clear `BUSY`, latch `CYCLES/MACS/
  FETCH_STATS`, raise `IRQ.DONE`.
- `STOP`: pulse the core abort/session reset, set `ABORTED` and `ERROR` with
  code 6, raise `IRQ.ERROR`.
- `SOFT_RESET`: clear session status/error/IRQ and abort the core. Segment
  bases, `IRQ_ENABLE`, trace config, and scratch are preserved.
- `START` while busy is ignored.
- `WATCHDOG != 0` counts while running; expiry aborts the core and sets code 3.

## 7. Memory model

The core emits `{segment, flat_local_offset}`. The hub subtracts the
segment's local base, checks the section-relative range, and adds the
programmed system base:

```
rel = flat_offset - LOCAL_BASE[seg]
valid = (flat_offset >= LOCAL_BASE[seg]) &&
        (rel + burst_bytes <= effective_limit[seg])
sys_addr = SEG_BASE[seg] + rel
```

- `SEG_BASE` must be 64-byte aligned.
- `effective_limit = SEG_LIMIT == 0 ? default_window : SEG_LIMIT`; the default
  windows are A 0x400, B 0x400, ACCUM 0x80, OUT 0x3780, CODE 0x40000.
- A data burst is VX `K` bytes, VE `2K`, VR `4K`; the AXI beat is 64 bytes
  and the DMA aligns down, so the limit/base alignment keeps every beat
  inside the segment.
- The core checks the data limit at dispatch and raises `MEM_FAULT`; the hub
  also guards the translated burst and reports `BUS_ERROR` on a violation.
- The external AXI master is standard and carries only the translated
  64-bit system address. The segment sideband is internal.

## 8. Trace records

64-bit record:

```
[63:32] timestamp
[47:32] pc
[55:48] event
[63:56] payload
```

Events: 1 START, 2 RETIRE, 3 DONE, 4 ERROR, 5 WATCHDOG, 6 ABORT,
7 OVERFLOW. Mode 0 is off; mode 1 is events only; mode 2 is events + retire
PC (the intended runtime default; the reset value is 0 = off); mode 3 also
records the done snapshot. Overflow sets
`IRQ.TRACE_OVF` and increments `TRACE_DROPS`; it never stalls the core.

## 9. Versioning

- Major protocol changes bump `VERSION.major` and may break the driver.
- Minor changes are additive in reserved bits/registers; the driver must
  ignore unknown `CAPS` bits.
- The IP release manifest records the protocol version, K/N/L/W, AXI widths,
  `NUM_SEG`, and register-map hash. The board repo pins the release; the
  host driver checks `ID`, `VERSION.major`, and `CAPS`.

## 10. Out of scope for v1

- Wider `ld/st` offsets or extra instruction-level segment selectors.
- A memory-resident job descriptor / command queue.
- Trace-to-memory DMA owned by the IP.
- Multi-instance aggregation (a board may instantiate several peripherals,
  each with its own control window).
