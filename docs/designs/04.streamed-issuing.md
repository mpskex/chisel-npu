# Design 04 — The streamed instruction-issuing model (in detail)

Companion to `02.streamed-dispatch.md`.  This document describes the exact
issuing model of `NpuProgramEngine` — the window/slot structure, the
scoreboard state and transitions, the per-slot readiness equations, the
issue selection, the unit queues, every chaining edge, the boundary gate,
the capture path, the completion paths, the session reset, and the drain —
plus the silicon-verified determinism fixes that make the model behave
exactly as designed.

Status: the engine is silicon-verified deterministic on the xc7k480t
(K = 16, N = 8, fabric 100 MHz), and the current FPGA build uses **W = 4**
(`src/main/scala/top/top.scala`); W = 8 spread the engine across 20 clock
regions and did not close timing on the xcvu9p at 200 MHz.  100/100 one-shot
captures correct, 0 wedges; the 3-mma + mma.last hardware test passes
repeatedly; the simulation regression suite (including a 200-run back-to-back
determinism check) is green.

## 1. Terminology

| Term | Meaning |
|:---|:---|
| *feed* | one MMALU issue tick; the mma operands enter the systolic array |
| *clct* | the MMALU collector pulse, `2n−1` ticks after a feed |
| *clctD* | `clct` delayed by `CAPTURE_DELAY` (=16) — when the capture is sampled and completions happen |
| *capture* | the value latched at `clctD` = the array's running-sum column at that instant |
| *boundary* | the PE-reset countdown started by `mma.last`; gates the next round's mma |
| *round* | one `mma.last`-terminated stream segment |

## 2. The five structures

### 2.1 The issue window (`W` slots)

A ring of `W` slots; each holds a decoded micro-op and its issue state:

```
DispatchSlot { valid, unit, family, rd, rs1, rs2, vs3, memWidth, sect,
               off, isStore, isMmaLast, illegal, useCapData,
               issued, done }
```

* `unit` ∈ {NONE, DMA, MMALU} — the execution unit the op targets.
* `useCapData` — a `vse` whose source register was produced by an mma
  capture (it consumes the capture queue, not the register file).
* Ring pointers `wHead`/`wTail` and occupancy `wCount` (all registers).
  `instr_ready = !wFull && !illegalAny`.

### 2.2 The scoreboard (physical VX granularity)

Alias-aware over the `L` VX slots (`L = K`, i.e. 16 at the FPGA top;
`VE[i]→VX[2i..2i+1]`, `VR[i]→VX[4i..4i+3]`):

* `vxWrMask(i)`  — a W-bit mask of window slots that are pending writers of
  VX[i] (the register's current producer(s)).
* `vxWrCap(i)`   — the last writer of VX[i] was an mma capture (vs an RF
  write).  This flag *survives* the producer's retirement, which is exactly
  why a late `vse` can still detect that it must consume the capture queue.
* `vxRdMask(i)`  — a W-bit mask of window slots currently waiting to READ
  VX[i] (in-flight readers).

Read/write slot sets are derived from the decoded op (`readSlotsL` /
`writeSlotsL`); the MMA writes `VX[4vd..4vd+3]`, a `vle` writes `VX[rd]`, a
`vse` reads its source.

### 2.3 The DMA request queue (`DMAQ_DEPTH = 4`)

```
DmaEntry { valid, inFlight, slotIdx, dir (0=vle, 1=vse, 3=fetch-fill),
           dmaWidth, rfAddr, l3Addr, storeDataValid, storeData(K×4N) }
```

`inFlight` = the request has been accepted by `NpuDmaEngine` and awaits its
`done`.  The queue head drives the DMA; the DMA serializes with the
frontend's fetch fills on the shared AXI master.

### 2.4 The vd FIFO (`FIFO_DEPTH = K`)

Pairs each mma feed's destination with its clct:

```
VdEntry { slotIdx, vd, isMmaLast, accum(K×4N) }
```

* enq at the feed (with the feed's `accum`), pop at `clctD`.
* The completion at `clctD` reads the head entry to know *which* slot the
  clct belongs to.

### 2.5 The capture-data queue (`CAPQ_DEPTH = K`)

```
CapEntry { valid, data(K×4N) }
```

* pushed at a non-last mma's `clctD` (the settled capture value);
* popped by a chained `vse` at its issue; the popped value is latched into
  the store request's `storeData`.

## 3. Window entry (the frontend streams into the window)

On `instr_valid && !wFull && !illegalAny` the op at `wTail` is decoded and
stored; `wCount` is net-adjusted against any same-cycle retirement (see §7).
The decoder's illegal set: decoder-illegal, `mma.reset`, `ld/st.rs1 > 3`, or
any family outside {NOP, LD, ST, MMA} (the VALU families are decode-only and
flagged illegal until the vector unit lands).

The capture-consumer detection at entry:

```
srmask(i) && vxWrCap(i)   →  useCapData = true   (for a store)
```

It deliberately does **not** require the producer to still be a pending
prior slot: the mma's `clctD` can retire the producer before the store word
streams into the window (variable MIG latency), so the store must still be
recognized as a capture consumer — otherwise the mma's capture sits in the
queue forever and `drain` never asserts (the original pc=4 wedge).

## 4. Per-slot readiness (the issue gate)

Slot `s` is ready iff all of:

1. **RAW** — every VX slot `s` reads has no pending writer *before* `s`:
   `(vxWrMask(i) & priorMask(s)) == 0` for every `i` in `readSlotsL(s)`.
   (`priorMask(s)` = valid slots earlier in the stream than `s`.)
2. **WAR** — every VX slot `s` writes has no earlier in-flight reader:
   `(vxRdMask(i) & priorMask(s)) == 0` for every `i` in `writeSlotsL(s)`.
3. **Unit room** — DMA: `!dmaQFull`; MMALU: `(fifoCount + feedValid) <
   FIFO_DEPTH && capQCount < CAPQ_DEPTH`.  The `+ feedValid` reserves the slot
   for the in-flight (registered) feed of the 2-stage pipeline so it can never
   overflow the FIFO.
4. **Boundary gate** — an MMA-family slot requires `boundaryCnt == 0`
   (a round's feeds are held until the previous round's PE reset finishes).
5. **mma.last ordering gate** — `mma.last` additionally requires that no
   *prior* pending non-last MMA exists:
   ```
   priorMma = OR over i of ( slots(i).valid && !slots(i).done
              && slots(i).unit == MMALU && !slots(i).isMmaLast
              && priorMask(s)(i) )
   ```
   This stops `mma.last` (which has no operand dependencies) from
   overtaking the mma, starting the boundary countdown, and gating the mma
   out entirely — the silicon bug where the mma never fed and the capture
   read a zero array.  Only *prior* slots count, so multi-round sessions
   cannot deadlock.

All five must hold; `illegalAny` also blocks issue (an illegal slot halts
the stream).

The **dependency** readiness (conditions 1, 2, 4, 5) is computed combinationally
and then **registered** (`slotsReadyR = RegNext(slotsReady)`); the **unit-room**
check (condition 3) stays combinational at issue time.  Registering the
scoreboard readiness removes the W×L scan from the issue→RF-read→feed cone
(the 200 MHz critical path on xcvu9p); issue then happens one tick after the
dependencies clear.

## 5. Issue selection

Each tick, the **oldest ready slot of each unit** issues, strictly in stream
order:

```
issueSel(s) = slotsReadyR(s) && slotUnitOk(s) && !issued && !done && firstForUnit(s)
firstForUnit(s) = no valid earlier slot of the same unit
```

The MMA slot that issues (stage 1) latches the feed control (`issueMma*`:
valid, slot, rd, rs1/rs2, vs3, mma.last) into **registers**; the DMA slot that
issues creates a `DmaEntry` (and pops the capture queue if it is a capture
consumer) in the same tick.  The **next** tick (stage 2) the registered feed
(`feedValid`, `feedSlot`, `feedRd`, `feedRs1/2`, `feedVs3`, `feedMmaLast`)
drives the RF read, the `in_a`/`in_b`/`in_accum` muxes, the MMALU control, and
the vd-FIFO enqueue.  This 2-stage MMALU feed pipeline halves the
issue→RF-read→FIFO logic depth; it adds one tick of feed latency (the tests
search the capture columns, so the shift is transparent).  The units still
issue in order but execute concurrently (DMA reads while the MMALU computes).

## 6. Execution units

### 6.1 DMA unit

The queue head drives `NpuDmaEngine`; `inFlight` is set on acceptance.
On `dma.io.done && dmaHead.valid && dmaHead.inFlight`:

* **vle** (`dir=0`): the RF write completed → clear the producer bit
  `vxWrMask(rfAddr)`, and `vxWrCap(rfAddr)=false` when the mask empties.
* **vse** (`dir=1`, RF source): the RF read completed → clear the reader
  bits.
* **fetch fill** (`dir=3`): the entry retires but **never touches a window
  slot** — a fill has no slot (`slotIdx` is a placeholder 0), and marking
  `slots(0).done` here would spuriously retire whichever real instruction
  owns ring slot 0 (the silicon bug where the mma never fed).
* the slot is marked `done` (vle/vse only), the entry retires, `dmaQCount--`.

### 6.2 MMALU unit

The feed drives the RF operand reads and the MMA control (`keep`, `busy`,
`use_accum`).  The systolic array computes the running outer-product column;
`clct` fires `2n−1` ticks after the feed, and the collector output settles
`CAPTURE_DELAY`(=16) ticks later — the capture is sampled at `clctD`.

At `clctD && fifoCount != 0` (the vd FIFO must actually own the clct — a
stale clct from a previous session still in the ShiftRegister would
otherwise retire a live slot):

* the head vd FIFO entry's slot is marked `done`;
* the producer tag `vxWrMask(VX[4vd..4vd+3])` is cleared;
* the capture value `array_out + fifo.accum` is pushed to the capture queue
  (non-last feeds only — `mma.last`'s "capture" is the same array state and
  must not enter the chain, or the next round's first `vse` would pop a
  stale value);
* the FIFO pops.

The fifo enq/pop accounting is net-correct when a feed and a clctD coincide
(one in, one out advances head and tail); a clctD with an empty FIFO is
ignored (no pop, no completion).

## 7. Window retirement and `wCount`

The head slot retires when `valid && done`.  `wCount` is computed as the
**net** of entry (+1) and retirement (−1) in the same cycle — with two
independent `when` blocks the later retirement's `wCount := wCount - 1`
would overwrite the entry's `wCount := wCount + 1`, losing one count per
coincidence and eventually underflowing the counter (seen as `wcount = 0xF`
on silicon).

## 8. The chaining edges (why no software timing is needed)

| edge | mechanism |
|:---|:---|
| `vle(rd=X) → mma(vs1=X)` | the DMA done clears X's tag; the waiting mma feeds the next tick — the feed cadence = the operand-arrival cadence |
| `mma(rd=vd) → vse(src=vd)` | the capture at `clctD` pushes the value and clears vd's tag; the vse (ready at the clctD) pops the capture queue at its issue and its store entry carries the latched value |
| `mma.last → next round` | the boundary countdown gates the next round's first mma; the round's vle/vse DMAs proceed during the window |

Register reuse (vd rings, operand slots) is entirely the software's job; the
scoreboard only enforces RAW/WAR.

## 9. The boundary gate

`boundaryCnt` (7 bits):

```
mma.last feed       → boundaryCnt := 6K − 1   (and at session start)
every tick          → boundaryCnt -= 1         (while ≠ 0)
keep = 0 pulse      → boundaryCnt === 2K       (the PE reset; the array is
                                                idle, so every PE latches 0)
mma-family readiness→ boundaryCnt === 0
```

`6K − 1` (rather than the original `4K − 1`) ensures the `keep = 0` reset
fires **after** the last capture's `clctD` — with `4K − 1` the reset landed
one tick before the mma's clct, zeroing the array before the capture
(`[0,0,0,0]` captures).  The longer countdown also delays the session-start
boundary so the array is provably idle when the reset pulse propagates.

## 10. Session reset

The frontend pulses `session_reset` at every start edge.  It clears the
**full** streaming state so a wedged or aborted session cannot contaminate
the next run:

* every slot's `valid`, `done`, `issued`, `unit`, `isMmaLast`, `family`,
  `rd/rs1/rs2/vs3`, `memWidth`, `sect`, `off`, `isStore`, `illegal`,
  `useCapData`;
* the scoreboard masks (`vxWrMask/vxWrCap/vxRdMask`);
* the DMA/capture/FIFO queues (valid/in-flight bits);
* `wCount/wHead`, `dmaQHead/Count`, `capQHead/Count`, `fifoHead/Count`;
* `boundaryCnt := 6K − 1`.

Notably it does **not** flush the `clctD` ShiftRegister (a delayed MMA
pulse), which is why the completion is additionally gated on a non-empty vd
FIFO (§6.2).

## 11. Drain

```
io.drain = !slotsAny && !dma.busy && dmaQCount == 0 && fifoCount == 0
            && capQCount == 0 && boundaryCnt == 0
```

The frontend asserts `done` at the last word (pc == PROG_LEN−1) only when
`instr_ready && drain`, i.e. the pipeline is provably empty — including the
boundary countdown, so a session cannot report done while its PE reset is
still propagating.

## 12. Frontend (the stream source)

`NpuProgramEngineFrontend` fetches 16-byte CODE lines through the shared DMA
(fetch-fill requests join the same `DmaEntry` queue as vle/vse), caches them
in an 8-set × 2-way LRU instruction cache, and streams words into the window
at its own pace (`instr_valid/instr_ready`).  It owns the ctrl_lite
registers (start/done/busy, STATUS pc/frames, ERR_INFO, PROG_LEN, the
trajectory) and the cache-invalidation on start.

## 13. Silicon-verified determinism fixes (this bring-up)

| # | Symptom on silicon | Root cause | Fix |
|:--|:---|:---|:---|
| 1 | intermittent wedge at pc=4, `busy=1`, `drain` never asserts | `useCapData` required a *pending prior* producer; a late store missed the capture → capQ stuck | detect by `vxWrCap` alone (§3) |
| 2 | counter underflow `wcount=0xF`, capQ wrapped | entry+retirement in the same cycle lost one `wCount` count | net `wCount` accounting (§7) |
| 3 | `[0,0,0,0]` captures every ~8 runs | free-running collector `cnt` landed on a bad diagonal | deterministic `cnt` reset at each collection window |
| 4 | `[0,0,0,0]` captures (periodic) | the `keep=0` PE reset fired before the mma's capture (`4K−1` countdown) | `6K−1` countdown (§9) |
| 5 | the mma never fed → zero array | the mma_last overtook the mma (no deps) and boundary-gated it | `priorMma` ordering gate (§4.5) |
| 6 | the mma never fed → zero array | the fetch-fill's placeholder `slotIdx=0` spuriously retired ring slot 0 (the mma) | fills never touch window slots (§6.1) |
| 7 | a stale clct from a previous session retired a live slot | `clctD` completion acted on an empty vd FIFO | gate completions on `fifoCount != 0` (§6.2) |

The one-shot path is now **100/100 deterministic**; the 3-mma + `mma.last`
session is **50/50 correct with per-capture running-sum verification**; the
hardware pytest suite (one-shot, multi-column, illegal-halt, status) passes;
and the simulation determinism regression (200 back-to-back runs) is green.
