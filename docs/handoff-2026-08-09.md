# Handoff — mma session model, simplified engine, run()-only driver (2026-08-09)

Supersedes the per-mma/keep=0 MAC model from the previous phase.  The NPU is
now programmed with **mma sessions** (the MMALU K-burst): a run of `mma`
feeds accumulating in the PEs, terminated by `mma.last`; each mma captures
one output column of the session product to its own vd.

## 2. The mma session (K-burst) model

```
# one session (m feeds) → m output columns
vle8  A[:,0] → VX[a0];  vle8  B[0] → VX[b0]
mma   vd0, a0, b0, c          # feed 0 → captures output column c0
vle8  A[:,1] → VX[a1];  vle8  B[1] → VX[b1]
mma   vd1, a1, b1, c          # feed 1 → captures output column c1
...
mma.last vdN, aN, bN, c       # session end (keep=0 boundary after its capture)
nop × nop_wait                # clct/drain window (≈ 2K+8 nops)
vse32 vd0 → OUT; vse32 vd1 → OUT; ...   # multiple vse32 store the columns
```

- **`mma` = one feed tick**: `ctrl = {busy=1, keep=1, use_accum=1}`,
  `in_a = VX[vs1]` (column), `in_b = VX[vs2]` (row), `in_accum = VR[vs3]`
  (x0 → 0).  The PEs accumulate `PE[i][j] += A[i]·B[j]` per feed.
- **Per-mma capture**: each mma's clct (2n−1 after its feed) captures one
  output column to its own `vd`:
  `vd_k[i] = Σ_m a_m[i]·b_m[col_k] + C[i]` (C added via use_accum at the
  capture).  Consecutive feeds → consecutive columns.
- **`mma.last`** marks the session end; the engine drops `keep` for one tick
  after its own capture — the MMALU boundary that resets the PEs.
- **`mma.reset` (funct3=2) is decoder-legal** (`mma_reset=1`) **but rejected at
  the engine level** (`npuProgramEngine`), not by the decoder. *(Correction,
  added during decoder-doc reconciliation: this earlier note called it
  "reserved/illegal".)*

### Sim-verified capture columns (issue-timing dependent — pin per test)

| Configuration | Capture columns |
|:---|:---|
| K=16, 3-mma session, engine-harness consecutive feeds | 6, 7, 8 |
| K=16, one-shot, engine-harness `issue()` | 2 (with the C-load: 1) |
| K=16, 3-mma session, frontend (spaced ~3–4-tick feeds) | 5, 8, 11 |
| K=32, 7-mma session, consecutive feeds | 25..31 |

The column index = `(feed_tick + 2n − n + 1 − cnt_start) mod n`-ish — a
function of the absolute issue timing.  The engine specs pin the offsets;
the driver hw tests locate the columns by search.

## 3. Engine — decode + raw-signal dispatch (the simplification)

`npuProgramEngine.scala` — states `IDLE, DMA_REQ, DMA_WAIT, DONE_1,
ILLEGAL` + a **capture FIFO** (vd queue, depth `2K+4`, back-pressure on
`instr_ready` when full):

- **`mma`/`mma.last`**: at IDLE accept → one feed tick (all three ctrl bits
  + combinational RF reads), **stays in IDLE** (so back-to-back issue =
  consecutive K-burst feeds at 1-tick spacing), pushes `vd` into the FIFO.
- **Capture**: on `mmalu.io.clct` (one pulse per feed, in order) → pop the
  FIFO, latch `io.out`, write `VR[vd]` the next tick.
- **Boundary**: `lastCapturePending` set on the `mma.last` feed; when *its*
  clct fires, `keep` drops for one tick (PE reset) — after the last capture,
  never right after the feed.
- **`keep` is held HIGH between feeds** (the MMALU idle pattern).  This is
  critical: `keep=0` during idle makes the PEs do `res := 0·0` and wipes
  every capture (see §7 gotchas).
- The DMA dispatch (vle/vse + frontend fetch fills) is unchanged; debug
  counters (mma accepted / clct captured) at ctrl 0x18/0x1C.
- **Removed**: the window FSM (W_IDLE/W_HOLD/W_DRAIN), MMA_FEED, operand
  latches (aBuf/bBuf/cBuf), drain counter, pipelined-issue gating.

`npuFrontend.scala` is **unchanged** (LRU 8×2×4-word prefetch cache, ctrl
map, `frames_done` on mma.last).  Its issue pace is ~3–4 ticks/word.

## 4. Driver — `ChiselNPU.run(instructions, memories)` (0.2.1)

```python
from chisel_npu_py import ChiselNPU, isa
npu = ChiselNPU()                       # NPUConfig default (K=16 silicon map)
result = npu.run(
    instructions=[isa.vle8(0, isa.SECT_A, 0),
                  isa.vle8(1, isa.SECT_B, 0),
                  isa.mma_last(2, 0, 1, 0),
                  *[isa.NOP] * 40,
                  isa.vse32(2, isa.SECT_OUT, 0)],
    memories={"A": a_bytes, "B": b_bytes},   # section → buffer
)
# result = {"A": <readback>, "B": <readback>, "OUT": int32[window]}
```

- `run()` stages the memories by section (native validates windows),
  stages the words into CODE, PROG_LEN → start (write 1 then 0 — start is
  edge-triggered!), waits done, raises `NPUProgramError(pc, err_info)` on
  illegal, returns everything read back incl. OUT (flat int32 of the OUT
  window; numpy inputs come back with the same dtype/shape).
- **Deleted**: `programs.py`, `inst_helper.py`, `ctrl.py`, `consts.py`.
  `config.py` = `NPUConfig` (sections/ctrl/nop_wait) + `default_config()`;
  `isa.py` (encoders) and `backend.py`/`native.cpp` (internal plumbing)
  unchanged.
- `tests/fake_native.py` models the session engine: PE matrix per session,
  **deferred captures** (applied before the first store — the hardware
  captures at the clct, after the session's feeds), `COL_OFF = 6`.
- Section map: A@0x4000_0000, B@0x4000_0400, ACCUM@0x4000_0800,
  OUT@0x4000_0880, CODE@0x4000_4000.  ctrl: CTRL=0x00, STATUS=0x08,
  ERR_INFO=0x0C, FETCH_STATS=0x10, PROG_LEN=0x14, DBG=0x18/0x1C.

## 6. OPEN ITEM — silicon session-capture alignment (the 2 xfails)

**Tests**: `test_one_shot_session`, `test_session_captures_columns` in
`drivers/chisel_npu_py/tests/test_program_engine.py` — both `xfail` with
reason "silicon session-capture phase depends on the frontend issue pacing".

**Symptom** (host probes): a 1-mma session on silicon captured `a[i]·1289`,
then `a[i]·399`, then `[2839, 5678, 8517, −7588, −4749, −1910]` — matching
**no** product column `a[i]·b[c]` (b = 100..115) and unstable across runs.
The operands were verified correct at the feed (VX dumps).  The sim gives
clean columns for the same engine + ctrl pattern; the divergence is the
absolute issue timeline (DDR/fetch latency, vle8 DMA stalls, cache misses
shift the feed ticks → the collector's cnt/walk phase at each clct).

**Planned fix** (in priority order):

1. **Diagnose on the host** (no RTL change): search each capture against all
   PE positions (rows / columns / transpose / diagonals / partial sums) to
   pin what the silicon actually samples; check run-to-run stability and
   whether the PE/boundary state from a previous session contaminates the
   next (the keep=1 idle preserves the PEs until the next boundary).
2. **Frontend mma fast-path** (`npuFrontend.scala`, ~30 lines): after an
   `mma` word, if the next cached word is also `mma`, latch it, `pc+1`, and
   go straight to `RUN_ISSUE` — consecutive mma issue at the 1-tick pace
   that the sim verifies produces clean consecutive columns.  Re-verify the
   frontend sim specs before the bitstream.
3. Rebuild (blocking wait) → bring-up → `make py-test-hw` — if the captures
   become clean columns, remove the `xfail` markers (the tests already
   assert by search).
4. If still not columns, the Phase-1 diagnosis directs the next step
   (boundary/collector-phase alignment or a synthesized-netlist check of
   the keep=1-idle pattern).

## 7. Gotchas learned (read before touching the engine)

- **keep semantics**: the MMALU idle pattern requires `keep=1` between
  feeds (accumulate 0·0, preserving the PEs).  `keep=0` during idle makes
  `res := 0·0` — every capture reads zero.
- **The boundary must come AFTER the last capture** (the `mma.last`'s own
  clct, 2n−1 after its feed) — a keep=0 boundary right after the feed wipes
  the PEs before the collector samples them (all-zero captures).
- The first-feed-reset variant (keep=0 on a session's first mma) was tried
  and produced non-column captures — do not resurrect it.
- The mma accept **must stay in IDLE** — the engine-harness consecutive
  poke and the frontend fast-path both rely on the 1-tick spacing.
- **Column offset is issue-timing dependent** — never hardcode it across
  different issue patterns; the specs pin per-test offsets, the hw tests
  search.
- **Register aliasing in tests**: the C operand (VR) aliases VX rows — the
  vd write clobbers the A/B operands post-feed (safe), but a C register must
  be disjoint from the operands at feed time (e.g. C=VR[3] = VX[12..15] with
  A=VX[4], B=VX[8]).
- Data must be int8-valid (poke/expect with the `s8` interpretation; values
  > 127 wrap and flip the sums negative).
- The start register is **edge-triggered**: `run()` writes 1 then 0 — a
  second run with start already 1 reads stale STATUS.
- The OUT section stores columns at `j·4K`; flat readbacks are
  column-major (transpose when comparing to row-major references).
- The fake's captures are **deferred** to before the first store (the
  hardware captures at the clct, after the session's feeds) — an in-order
  fake gives the wrong (partial) values.
- The selftest/int32 readbacks must be viewed as bytes before comparing to
  uint8 patterns.
